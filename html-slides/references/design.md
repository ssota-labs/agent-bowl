# 디자인 원칙

(Anthropic `pptx` 스킬의 디자인 가이드를 HTML/CSS·국문 업무 문서에 맞게 옮긴 것)

## 시작 전에

- **주제에 맞는 팔레트를 고른다.** 그 색을 완전히 다른 발표에 그대로 옮겨도 어울린다면, 고른 게 아니라 기본값을 쓴 것이다.
- **지배색을 만든다.** 한 색이 시각 무게의 60–70%, 보조 1–2개, 강조 하나. 다 똑같은 비중이면 아마추어처럼 보인다.
- **명암을 교차시킨다.** 표지·간지·결론은 `.slide.dark`, 본문은 밝게 (샌드위치 구조). 아니면 전체를 어둡게 밀어붙여 고급스럽게.
- **모티프 하나를 정해 끝까지 반복한다.** 카드 왼쪽 5px 강조 바(`.card.edge`), 원형 아이콘 칩(`.chip`), 둥근 이미지 프레임 중 **하나만** 골라 전 장에 반복.
- **강조색은 아껴 쓴다.** 한 장에 강조색이 3곳 이상 나오면 강조가 아니다.

## 타이포

국문 슬라이드는 **Pretendard** 가 사실상 표준. `deck.css` 의 스택이
`Pretendard → Apple SD Gothic Neo → Noto Sans KR → system-ui` 라 macOS 에서는 바로 예쁘게 나온다.
웹폰트를 확실히 박고 싶으면 `theme.css` 상단에 추가:

~~~css
@import url("https://cdn.jsdelivr.net/gh/orioncactus/pretendard@v1.3.9/dist/web/variable/pretendardvariable.min.css");
~~~

(오프라인 환경이면 넣지 말 것 — 렌더가 늦어지고 캡처가 흔들린다.)

- 국문은 자간을 살짝 좁힌다 (`letter-spacing: -0.02em`) — `.t-title`/`.t-head` 에 이미 적용됨.
- 숫자는 `font-variant-numeric: tabular-nums` (`.t-kpi`, `.tbl td.num` 적용됨).
- **크기 대비를 확실히.** 제목 52px 옆에 본문 19px. 애매한 중간 크기를 늘리지 말 것.
- 글꼴은 한 덱에 2종 이내.

## 각 장의 구성

**모든 슬라이드에 시각 요소가 하나는 있어야 한다.** 제목+불릿만 있는 장은 기억에 안 남는다.

레이아웃 선택지:
- 좌우 2단 (설명 왼쪽 / 도식·차트 오른쪽)
- 아이콘 칩 + 텍스트 행 반복
- 2×2 / 2×3 그리드 카드
- 반쪽 블리드 (`.bleed-l` / `.bleed-r`) 이미지 위 콘텐츠 오버레이
- 큰 숫자 콜아웃 (`.t-kpi` 3장 나열)
- 비교 2단 (전/후, 장/단, 안A/안B)
- 타임라인·프로세스 (`.steps`)

## 여백

- 슬라이드 안쪽 여백 64px (`--pad`) 유지. 가장자리에 24px 안쪽으로 뭔가 붙으면 QA 가 경고한다.
- 블록 사이 간격은 `--gap`(28px) 하나로 통일. 20px, 24px, 30px 을 섞지 말 것.
- 다 채우지 말 것. 빈 공간이 위계를 만든다.

## 피할 것

- **제목 아래 밑줄/액센트 선** — AI가 만든 티가 가장 많이 나는 요소. 여백이나 배경색으로 구분할 것.
- 모든 장을 같은 레이아웃으로 반복
- 본문을 가운데 정렬 (제목만 가운데, 문단·목록은 왼쪽)
- 흐린 배경에 흐린 글자 (대비 부족)
- 한 장만 공들이고 나머지는 기본값
- 텍스트만 있는 장
- 12개 넘는 `data-region` (색이 겹쳐 지목이 깨진다)

## 자기 점검

작업 후 `shot` 이미지를 직접 열어보고 아래를 확인한다. 하나도 안 걸리면 덜 본 것이다.

- 요소가 겹치거나 글자를 뚫고 지나가는 곳
- 잘리거나 넘친 텍스트
- 한 줄 제목 기준으로 잡아둔 장식이 두 줄 제목 때문에 어긋난 곳
- 출처/푸터가 위 콘텐츠와 붙은 곳
- 간격이 들쭉날쭉한 곳 (한쪽은 텅 비고 한쪽은 빽빽)
- 열 간 정렬이 안 맞는 곳
- 대비가 약한 글자·아이콘
- 폭이 좁아 과하게 줄바꿈되는 텍스트 상자
- 남아 있는 플레이스홀더 (`—`, `여기에 내용을 채운다`, `SECTION`)
