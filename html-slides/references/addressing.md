# 영역 주소 해석 — 사용자 말 → `data-region` 확정

수정 요청을 받으면 **추측하기 전에 주소록부터 읽는다.**

~~~bash
python3 <스킬 디렉터리>/scripts/slidecraft.py map <슬라이드.html>
~~~

(구조를 바꾸지 않았다면 `<덱>/.slidecraft/regions.md` 캐시를 읽어도 된다.
구조를 바꿨다면 번호·색이 밀리므로 **반드시 재생성**한다.)

## 주소록 표 읽는 법

~~~
| # | 선택모드색 | 실제색 | 이름 | id | 위치 | 좌표(%) | 역할 | 내용 |
| 6 | 청록 | 남색 | 핵심 인사이트 박스 | `insight` | 우측중앙 · 3행 좌→우 2/3 | x 64–95 · y 50–66 | 박스 | 엔터프라이즈가 성장을 끌었다 … |
~~~

| 컬럼 | 뜻 | 사용자가 이렇게 부른다 |
|------|----|----------------------|
| `#` | 문서 순서 = 배지 번호 = 팔레트 색 번호 | "6번", "여섯 번째 박스" |
| `선택모드색` | 선택 모드 오버레이 테두리 색 | "청록 박스", "민트색 상자" |
| `실제색` | 화면에 실제로 칠해진 배경색. 괄호는 상위에서 물려받은 색(=이 영역이 직접 칠하지 않음) | "남색 박스", "빨간 카드" |
| `이름` | `data-label` | "핵심 인사이트 박스", "인사이트" |
| `id` | `data-region` | "insight" |
| `위치` | 3×3 존 + 행/열 순번 | "오른쪽 가운데", "세 번째 줄 두 번째" |
| `좌표(%)` | 슬라이드 대비 x/y 범위 | 상대 표현("~의 오른쪽") 계산용 |
| `역할` | 제목/목록/표/차트/이미지/푸터/박스 | "제목", "표", "출처" |
| `내용` | 텍스트 앞부분 | "매출 얘기하는 박스", "'엔터프라이즈' 나오는 데" |

## 해석 절차

후보 집합 = 슬라이드의 모든 영역에서 시작해, 사용자 표현에 나온 **단서마다 교집합**을 취한다.

1. **번호** — "3번", "세 번째", "#3" → `#` 컬럼 일치. 강한 단서, 단독으로 확정 가능.
2. **색상** — 아래 색 동의어 표로 정규화한 뒤 **`선택모드색` 과 `실제색` 두 컬럼 모두**에서 찾는다. 강한 단서. 충돌 처리는 "색이 겹칠 때" 절 참고.
3. **id** — 영문 슬러그가 그대로 나오면 일치.
4. **이름** — `이름` 컬럼에 부분 문자열 포함 (조사 제거 후: "매출 카드는" → "매출 카드").
5. **내용** — `내용` 컬럼에 사용자가 인용한 문구가 포함되는지. 실제 슬라이드 HTML을 grep해도 된다.
6. **위치** — 아래 위치 동의어 표로 정규화 → `위치` 컬럼 일치. **약한 단서** (한 존에 여러 개일 수 있다). 다른 단서와 교집합으로 쓴다.
7. **역할** — "제목", "표", "차트", "출처/푸터", "목록" → `역할` 컬럼 일치.
8. **상대 표현** — "차트 오른쪽", "제목 바로 아래", "142억 옆" → 기준 영역을 먼저 확정한 뒤 `좌표(%)` 로 계산 (아래 참조).

결과가
- **정확히 1개** → 진행. 답변 첫 줄에 `N번 · 색 · 이름(id)` 형식으로 되짚는다.
- **2개 이상** → 각 후보를 `shot --focus <id>` 로 찍어 사용자에게 보내고 고르게 한다.
- **0개** → 선택 모드 스크린샷 + 주소록을 보내고 다시 물어본다. **절대 아무거나 골라 고치지 않는다.**

## 위치 동의어

| 정규화 | 사용자 표현 |
|--------|------------|
| 좌상단 | 왼쪽 위, 좌측 상단, 왼쪽 맨 위, 좌상, top-left, 11시 방향 |
| 상단중앙 | 위쪽 가운데, 맨 위 중앙, 위 중간, top-center |
| 우상단 | 오른쪽 위, 우측 상단, 오른쪽 맨 위, top-right, 1시 방향 |
| 좌측중앙 | 왼쪽 중간, 좌측 가운데, 왼쪽 허리, middle-left |
| 정중앙 | 한가운데, 정가운데, 화면 중앙, center |
| 우측중앙 | 오른쪽 중간, 우측 가운데, middle-right |
| 좌하단 | 왼쪽 아래, 좌측 하단, 왼쪽 맨 아래, bottom-left |
| 하단중앙 | 아래쪽 가운데, 맨 아래 중앙, bottom-center |
| 우하단 | 오른쪽 아래, 우측 하단, bottom-right |
| 상단 가로 전폭 | 맨 윗줄, 상단 띠, 헤더 줄 |
| 하단 가로 전폭 | 맨 아랫줄, 하단 띠, 푸터 줄 |
| 전체 배경 | 배경, 뒷판, 전면 |

**행/열 표현** — 표의 `위치` 컬럼에 `2행 좌→우 3/3` 같은 정보가 붙는다.
- "두 번째 줄", "가운데 줄", "아래 줄" → 행(row)
- "왼쪽 것", "가운데 것", "오른쪽 끝", "세 개 중 두 번째" → 열(col)
- "위쪽 카드 세 개 중 마지막" → 그 행의 `col == rowCount`

**세로 위치 애매어**: "위쪽"은 상단 존일 수도 있고 "제목 바로 아래 줄"일 수도 있다. 슬라이드에 상단 헤더가 따로 있으면, 사용자가 "위쪽 박스"라고 할 때 보통 **헤더가 아니라 그 아래 첫 콘텐츠 행**을 뜻한다. 헤더/푸터는 보통 "제목", "맨 위 제목", "출처", "푸터"라고 따로 부른다.

### 색이 겹칠 때

이 12색은 **선택 모드 오버레이 색**이지 슬라이드 디자인 색이 아니다. 주소록의 `실제색` 컬럼이 실제로 칠해진 배경색이다. 둘 중 어느 쪽을 뜻하는지는 이렇게 판단한다.

1. `실제색` 에 정확히 일치하는 영역이 **하나뿐**이면 그걸로 확정한다. 사람은 보통 눈에 보이는 색을 말한다.
2. 1번이 안 되고 `선택모드색` 에 일치하는 게 하나면 그걸로 확정한다.
3. **양쪽에서 서로 다른 후보가 나오면** 추측하지 말고 `shot --focus` 로 둘 다 찍어 확인받는다.
4. `실제색` 이 `(흰색)` 처럼 괄호면 그 영역은 배경을 직접 칠하지 않은 것이다 — 사용자가 색으로 부를 리 없으니 후보에서 낮춘다.

직전 응답에서 선택 모드 스크린샷을 보냈다면 사용자가 오버레이 색 배지를 보고 말했을 가능성이 높으니 2번 우선순위를 올린다.

## 상대 표현 계산

`좌표(%)` 컬럼(x 시작–끝, y 시작–끝)으로 판정한다. 기준 영역을 R이라 할 때:

| 표현 | 조건 |
|------|------|
| R의 오른쪽 | `x시작 ≥ R.x끝` 이고 y 범위가 R과 겹침 |
| R의 왼쪽 | `x끝 ≤ R.x시작` 이고 y 범위가 R과 겹침 |
| R 바로 아래 | `y시작 ≥ R.y끝` 이고 x 범위가 겹치며, 그런 것 중 y시작이 가장 작음 |
| R 바로 위 | `y끝 ≤ R.y시작` 이고 x 범위가 겹치며, 그런 것 중 y끝이 가장 큼 |
| R 옆 / 나란히 | 같은 행(row)이고 col 이 ±1 |

## 2레벨 주소 (부품)

블록 전체가 아니라 그 안의 조각을 고쳐야 할 때가 많다.
주소록 아래쪽 "부품(2레벨)" 목록에 `kpi-revenue.value` 형태로 나온다.

- "매출 카드의 숫자만 바꿔줘" → `kpi-revenue.value`
- "제목 위 작은 영문 라벨" → `header.eyebrow`
- "출처 문구" → `footer.source`

부품까지 화면으로 보여주려면 선택 모드에서 `2` 키, 또는 `?mode=select&level=2`.

## 예시 (방법을 보여주는 것이지, 문구 대조표가 아니다)

가정: 주소록에 `header`(1 빨강/실제 흰색), `metric-a·b·c`(2·3·4, 2행 카드 3장),
`chart`(5 보라, x 5–62), `callout`(6 청록/실제 남색, x 64–95 y 50–66),
`caveat`(7 분홍/실제 빨강, x 64–95 y 70–85), `footer`(8 노랑) 이 있다.

**"오른쪽 중간에 있는 남색 상자 말투 좀 부드럽게"**
색 단서 "남색" → `실제색` 컬럼에서 유일 일치 `callout`. 위치 단서(우측중앙)도 일치 → 확정.
답변: "`6번 · 청록 · 핵심 인사이트(callout)` 문구를 다듬었습니다."

**"맨 아래 오른쪽 거 지워줘"**
위치 = 우하단 → `caveat` 단독 → 확정. `footer` 는 '하단 가로 전폭' 이라 "오른쪽"과 안 맞는다.

**"가운데 숫자 카드, 316이 아니라 320이야"**
행 = 카드 행, 열 = 2/3 → `metric-b`. 바꿀 건 카드 전체가 아니라 숫자이므로 부품 `metric-b.value`.

**"그래프 옆에 있는 박스"**
기준 `chart`(x 5–62) → 오른쪽 후보 `callout`, `caveat` **두 개** → 확정 불가.
`shot --focus callout`, `shot --focus caveat` 를 찍어 보내고 고르게 한다.

**"빨간 거 글씨 키워줘"**
`실제색 = 빨강` → `caveat`. `선택모드색 = 빨강` → `header`.
서로 다른 후보가 나왔으므로 **추측 금지** → 둘 다 focus 로 찍어 확인.

**"네 번째"**
`#4 metric-c` 로 확정 가능하지만, 사용자가 배지 번호를 보고 말한 게 맞는지 애매하다.
직전에 선택 모드 이미지를 보낸 적이 있으면 진행, 아니면 focus 로 확인.
