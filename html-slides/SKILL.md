# html-slides — 말로 지목해서 고치는 HTML 슬라이드

## 가장 먼저 할 일 — 미리보기를 띄운다

**슬라이드 작업을 시작하면(만들든 고치든) 제일 먼저 라이브 미리보기를 켠다.**

~~~bash
python3 $S preview <덱경로>      # 브라우저가 자동으로 열린다. 백그라운드로 실행할 것
~~~

사용자는 개발자가 아니다. 파일 경로를 찾지 못하고, 브라우저를 새로고침해야 한다는 것도 모른다.
미리보기 창이 **사용자가 보는 유일한 화면**이다.

- 슬라이드 파일이나 `theme.css` 를 고치면 **0.6초 안에 사용자 화면이 알아서 바뀐다.** 다시 띄우라고 할 필요 없다
- 보고 있던 페이지 번호가 유지된다
- 화면 아래 **`HTML 저장`** 버튼 = 완성본(`--clean` 공유본) 다운로드, **`PDF 저장`** = 인쇄창
- **`선택 모드`** 버튼 = 영역에 번호·색·이름 배지. 사용자에게 "몇 번 박스"를 알려줄 때 이걸 켜라고 안내한다
- 이미 떠 있으면 다시 실행하지 않는다 (포트가 물려 있으면 자동으로 다음 포트로 넘어간다)

작업을 마쳤을 때 사용자에게 파일 경로를 알려주는 대신 **미리보기 주소와 `HTML 저장` 버튼을 안내한다.**
스크린샷(`shot`)은 사용자 확인용이 아니라 **네가 직접 눈으로 검토하기 위한 것**이다 (아래 QA 절).

### "보여줘" 계열은 전부 이 명령이다

사용자는 명령어를 모른다. 아래처럼 말하면 **되묻지 말고 바로 `preview` 를 띄운다.**

> 프리뷰 띄워줘 · 미리보기 보여줘 · 슬라이드 보여줘 · 편집기 띄워줘 · 결과 좀 보자 ·
> 어떻게 나왔어? · 지금 상태 보여줘 · 브라우저로 열어줘 · 화면에 띄워줘 · 확인하고 싶어

판단 규칙:

1. 덱이 없으면 → `new` 로 만들고 → `preview`
2. 덱이 있는데 미리보기가 안 떠 있으면 → `preview` (백그라운드)
3. 이미 떠 있으면 → **다시 실행하지 않는다.** "이미 열려 있는 창이 자동으로 바뀝니다"라고 알려준다
4. "PDF로 줘" / "파일로 줘" → 미리보기의 `PDF 저장` · `HTML 저장` 버튼을 안내한다.
   그래도 파일이 필요하면 `build --clean` / `pdf`

`preview` 는 항상 최신 파일을 읽어 그리므로 **따로 `build` 를 먼저 돌릴 필요가 없다.**

### 이 스킬을 처음 쓰는 사용자에게 (첫 응답)

첫 응답에서 미리보기 주소와 함께 이 정도만 짧게 알려준다. 길게 늘어놓지 말 것.

> 미리보기 창을 띄웠습니다. 이 창은 **계속 켜두시면 됩니다** — 제가 슬라이드를 고칠 때마다
> 알아서 바뀝니다. 새로고침하실 필요 없어요.
>
> - 고치고 싶은 곳은 **말로** 알려주세요. "왼쪽 위 파란 박스", "3번 박스", "매출 숫자" 다 통합니다.
>   어디를 뭐라고 부르는지 모르시겠으면 아래 **`선택 모드`** 버튼을 눌러 보세요. 영역마다
>   번호·색·이름이 붙습니다.
> - 다 되면 **`HTML 저장`** 버튼으로 파일을 받으시면 됩니다. 발표용 PDF 는 `PDF 저장`.

사용자가 이미 익숙해 보이면(용어를 쓰거나, 이전에 만든 덱을 고치는 중이면) 이 안내는 생략한다.

## 이 스킬이 푸는 문제

사용자는 화면에서 영역을 드래그해 "여기"라고 짚어줄 수 없다. 말로 설명해야 한다.
그래서 **모든 슬라이드의 모든 블록에 4중 주소를 미리 붙여둔다.**

| 주소 | 예시 | 어디서 나오나 |
|------|------|--------------|
| **번호** | "3번 박스" | 문서 순서 = 배지 번호 |
| **색상** | "빨간 박스", "청록 박스" | 선택모드 오버레이 색(번호 N == 팔레트 N번) + **실제 렌더링 배경색** 둘 다 주소록에 있다 |
| **위치** | "좌측 상단", "2행 가운데", "차트 오른쪽" | 실제 렌더 좌표에서 계산 |
| **이름/내용** | "매출 KPI 카드", "이탈률 나오는 박스" | `data-label` + 텍스트 미리보기 |

이 4가지가 **하나의 표(영역 주소록)** 에 모여 있고, 그 표는 스크린샷 없이도 읽을 수 있다.
사용자가 뭐라고 부르든 그 표에서 찾아 해석하면 된다.

**미리보기 모드 / 선택 모드**
- `미리보기` — 최종 결과 그대로. 사용자에게 "이렇게 나옵니다" 보여줄 때.
- `선택 모드` — 각 영역에 색상 점선 테두리 + 반투명 오버레이 + `번호 · 색 · 이름` 배지가 붙고, 슬라이드 아래에 주소록 표가 붙는다. **사용자가 "어디를 뭐라고 불러야 하는지" 배우는 화면.**
- `포커스 모드` — 한 영역만 남기고 전체를 흐리게. **"이 영역 말씀하신 거 맞죠?" 확인용.**

## 명령어

아래 경로는 **이 스킬 디렉터리 기준**이다. 먼저 스킬 위치를 변수에 잡아두고 쓴다.

~~~bash
S=<이 SKILL.md 가 있는 디렉터리>/scripts/slidecraft.py

python3 $S preview <덱경로>                    # ★ 라이브 미리보기 (브라우저 자동 실행 · 자동 갱신)
python3 $S new <덱경로> --title "제목"        # 덱 스캐폴드 (assets 복사 포함)
python3 $S add <덱경로> <slug> --title "제목"  # 슬라이드 추가
python3 $S worldmap <덱경로> --highlight KR,JP,US --marker KR,JP,US   # 세계지도 (핀 포함)
python3 $S map <덱|슬라이드.html>              # ★ 영역 주소록 (마크다운 표)
python3 $S shot <덱|슬라이드.html> --mode both # 미리보기 + 선택모드 PNG
python3 $S shot <슬라이드.html> --focus <id>   # 한 영역만 스포트라이트
python3 $S shot <슬라이드.html> --mode select --grid   # 3×3 위치 격자까지
python3 $S qa <덱|슬라이드.html>               # 넘침·겹침·여백·글자크기 자동 검사
python3 $S build <덱경로>                      # dist/deck.html — 작업본 (선택 모드 + 툴바 포함)
python3 $S build <덱경로> --clean              # dist/deck-share.html — ★공유본 (도구 흔적 0)
python3 $S pdf <덱경로>                        # dist/deck.pdf (정확한 16:9)
~~~

브라우저는 전역 설치된 `agent-browser`를 쓴다. 추가 설치 필요 없음.
결과는 `<덱>/.slidecraft/` 아래에 캐시된다 (`regions.json`, `regions.md`, `shots/`).

## 덱 구조

~~~
<덱>/
├── deck.json          제목 / 캔버스 크기
├── assets/
│   ├── deck.css       프레임워크 — 고치지 않는다
│   ├── theme.css      ★ 팔레트·폰트 — 덱마다 여기만 고친다
│   ├── worldmap.css   지도 스타일 — 색은 theme.css 의 --wm-* 변수로 덮는다
│   ├── regions.css    선택 모드 스타일
│   └── regions.js     런타임 (주소 계산 / 오버레이 / QA)
├── slides/01-*.html   슬라이드 1장 = 파일 1개  ← 실제 작업 대상
└── dist/
    ├── deck.html        작업본 — 선택 모드·툴바 포함. 사용자와 다듬을 때 쓴다
    ├── deck-share.html  공유본 — 도구 흔적 0. 남에게 보낼 땐 반드시 이걸 보낸다
    └── deck.pdf         PDF (960×540pt)
~~~

**산출물을 전달할 때는 `--clean` 공유본을 준다.** 작업본에는 선택 모드 런타임과
`data-region`/`data-label` 같은 작성용 속성이 남아 있어서, 받는 사람 입장에선 군더더기다.

## 마크업 규칙 (반드시 지킬 것)

~~~html
<section class="slide" data-slide="02" data-title="2026 상반기 실적">
  <div class="card" data-region="kpi-revenue" data-label="매출 KPI 카드">
    <p class="t-cap"  data-part="label">누적 매출</p>
    <p class="t-kpi"  data-part="value">142억</p>
  </div>
</section>
~~~

1. **주소를 붙일 블록마다 `data-region="영문-슬러그"`.** 이게 없으면 지목이 불가능하다.
2. **`data-label="한글 이름"` 은 사실상 필수.** 사용자가 실제로 부를 이름을 넣는다.
   `"매출 KPI 카드"`, `"핵심 인사이트 박스"`, `"하단 푸터"` 처럼.
3. 블록 안의 조각은 `data-part="label|value|title|body|source..."` → 주소는 `kpi-revenue.value`.
4. **한 슬라이드의 `data-region` 은 12개 이하.** 팔레트가 12색이라 넘으면 색이 겹친다.
   블록이 많으면 컨테이너 단위로 묶어라 (`kpi-1/2/3` 각각 말고 필요하면 `kpis` 하나로).
5. 배경으로 깔리는 요소(`.bleed*`)에는 `data-overlap-ok` 를 붙여 겹침 경고를 끈다.
6. 슬라이드 파일에는 `deck.css → theme.css → regions.css` 순서로 링크하고 맨 아래 `regions.js`.
   지도가 들어가는 장은 `theme.css` 뒤에 `worldmap.css` 를 하나 더 넣는다 (`worldmap` 명령이 알아서 넣어 준다).

## 작업 흐름

### 새로 만들 때

1. `new` 로 스캐폴드 → **`preview` 를 백그라운드로 띄운다** → 사용자에게 주소를 알려준다
2. `assets/theme.css` 에서 **주제에 맞는 팔레트를 새로 고른다** (기본값 그대로 쓰지 말 것 — [references/design.md](references/design.md))
3. 슬라이드 개요를 먼저 사용자와 합의 (몇 장, 각 장 메시지 한 줄)
4. 슬라이드별로 HTML 작성 — 레이아웃 레시피는 [references/authoring.md](references/authoring.md).
   지도가 들어가면 [references/maps.md](references/maps.md)
5. `qa` 로 자동 검사 → 0 오류까지 수정
6. `shot --mode both` 로 캡처 → **직접 이미지를 눈으로 검토** (아래 QA 절)
7. 사용자에게는 **미리보기 화면**을 안내한다 (이미 갱신돼 있다). 주소록 표를 답변에 요약
8. 다 됐으면 `HTML 저장` 버튼을 누르라고 안내한다. 파일이 꼭 필요하면 `build --clean` / `pdf`

### 고칠 때 (핵심 경로)

0. 미리보기가 안 떠 있으면 먼저 `preview` 를 띄운다 (고친 결과를 사용자가 즉시 본다)
1. `map` 으로 주소록을 읽는다 (이미 `.slidecraft/regions.md` 에 있으면 그걸 읽어도 된다. 단 **구조를 바꾼 뒤에는 반드시 재생성** — 번호와 색은 문서 순서를 따르므로 밀린다)
2. 사용자 표현 → 영역 확정. 해석 규칙은 [references/addressing.md](references/addressing.md)
3. **후보가 1개면** 그대로 진행하되, 답변 첫 줄에 확정한 영역을 되짚는다:
   > `6번 · 청록 · 핵심 인사이트 박스(insight)` 를 고쳤습니다.
4. **후보가 2개 이상이거나 0개면** 추측하지 말고 `shot --focus <후보id>` 로 후보 이미지를 보내 확인받는다
5. 수정 → `qa` → `shot` → 사용자에게 결과 전달

### 사용자가 부르는 법을 모를 때

첫 응답에서 선택 모드 스크린샷과 함께 이렇게 안내한다:

> 영역은 **번호(3번)**, **색(빨간 박스)**, **위치(좌측 상단 / 두 번째 줄 가운데)**, **이름(매출 KPI 카드)** 중 아무거나로 불러 주세요. 넷 다 통합니다.

## QA (건너뛰지 말 것)

**1단계 — 자동 검사.** `qa` 는 이걸 잡는다: 슬라이드 밖 이탈, 내용 잘림, 텍스트가 영역 밖으로 넘침, 영역 겹침, 간격/여백 부족, 12px 미만 글자. 오류 0건이 될 때까지 고친다.

**2단계 — 눈으로 검사.** 자동 검사는 "정렬이 어긋났다", "여백이 들쭉날쭉하다", "대비가 약하다", "차트 라벨이 막대와 안 맞는다" 를 못 잡는다. `shot` 결과 PNG 를 **반드시 직접 읽어서 본다.** 문제가 하나도 안 보이면 덜 본 것이다.

**3단계 — 재검증.** 고친 뒤 다시 찍는다. 한 곳을 고치면 다른 곳이 깨진다.

3장 이상이면 서브에이전트에게 이미지 검토를 맡기는 편이 낫다 (본인은 코드를 봐서 "있어야 할 것"이 보인다).

## 하지 말 것

- `data-region` 없이 슬라이드를 만들기 — 나중에 지목이 불가능해진다
- `data-label` 을 영어로 쓰거나 비워두기 — 사용자는 한글로 부른다
- 구조를 바꾸고 주소록을 재생성하지 않기 — 번호·색이 밀려서 대화가 어긋난다
- 사용자 표현이 모호한데 하나를 골라서 조용히 고치기 — `--focus` 로 확인부터
- `deck.css` / `worldmap.css` 를 덱마다 고치기 — `theme.css` 에서 변수만 덮어쓴다
- 자동 QA만 돌리고 스크린샷을 안 보기
- 미리보기를 안 띄우고 작업하기 — 사용자는 파일을 열 줄 모른다
- 사용자에게 `dist/deck.html` 같은 **파일 경로를 알려주고 끝내기** — 미리보기 주소와 `HTML 저장` 버튼을 안내한다
- 슬라이드 `<head>` 안에 `<style>` 로 스타일 넣기 — **`build` 는 `<section>` 만 가져가므로 그 CSS 는 사라진다.**
  공용 스타일은 `assets/*.css`, 한 곳만 쓰는 값은 인라인 `style=""` 로
