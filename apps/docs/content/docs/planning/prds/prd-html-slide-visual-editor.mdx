## 한 줄

미리보기 화면에서 슬라이드 영역을 눌러 고치면, 같은 변경이 디스크의 HTML·테마·템플릿 파일에 저장된다.

## 문제

지금은 에이전트가 HTML을 고치고 사용자가 미리보기로만 확인한다. 작은 글자·색·간격 수정도 말로 다시 지시해야 한다. 사용자는 Figma/Framer처럼 클릭해서 고치고 싶지만, 그 결과가 에이전트가 다루는 원본 파일과 어긋나면 안 된다. 인트라넷에서는 Node·CDN에 의존한 공유본도 열리지 않아야 한다.

## 무엇을 저장·보여 주는가

| 이름 | 예시 | 왜 필요한가 |
|------|------|-------------|
| 슬라이드 HTML | `slides/02-kpi.html` | 장표 내용·영역 주소의 원본 |
| 덱 테마 | `assets/theme.css`의 `--brand` 등 | 덱 전체 색·톤 |
| 템플릿 HTML | `templates/kpi-grid.html` | 새 장표를 복제하는 원형 |
| 미리보기 선택 | `kpi-revenue.value` | 말로도 UI로도 같은 곳을 가리킴 |

## 목표

- 영역(`data-region` / `data-part`)을 클릭하면 우측 패널에서 글·공통 시각 속성을 고친다.
- 변경은 원본 파일을 최소 범위로 패치해 저장한다. 미리보기 DOM은 원본이 아니다.
- 덱 색 팔레트와 템플릿을 웹에서 보고 고치고, 템플릿으로 새 슬라이드를 만든다.
- 에이전트가 파일을 직접 고쳐도 미리보기가 따라오고, 충돌 시 조용히 덮어쓰지 않는다.
- `build --clean` 공유본에는 편집기 흔적이 없고 Node/CDN 없이 열린다.

## Non-goals

- 임의 HTML 요소 전체 IDE, 자유 드래그 레이아웃, 협업 OT/CRDT
- React/Lit 기반 슬라이드 런타임으로의 전환
- 인트라넷 PC에 npm/node 설치를 요구하는 배포

## 비기능

- 미리보기 서버는 localhost Python만 사용한다.
- 패치는 들여쓰기·주석·속성 순서를 보존한다.
- 파일 revision(hash)으로 외부 수정과 충돌을 감지한다.

## 성공 지표

- 영역 클릭 → 패널 수정 → 원본 HTML에 동일 값이 남는다.
- 테마 색 변경 후 모든 슬라이드에 반영된다.
- 템플릿을 고치고 새 슬라이드로 복제할 수 있다.
- clean HTML에 editor/bridge/write API 흔적이 없다.
- 에이전트가 같은 파일을 고치면 409 또는 안전한 재적용만 허용된다.

## 결과 계약

원본은 항상 `slides/*.html`, `templates/*.html`, `assets/theme.css`, `deck.json`이다. 편집기 UI는 투영이며 저장의 유일한 경로는 서버의 typed patch API다.
